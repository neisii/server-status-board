# server-status-board

`digital-clock-board`와 같은 자리(터미널 분할)에 띄워 두는 서버 구동 현황 보드. 네가 지정한 외부 상태 스크립트를 10초 간격으로 폴링해서, 프로젝트마다 포트·브랜치·미커밋·헬스를 한 줄씩 보여준다. 상태 판정 로직은 전부 그 외부 스크립트에 있고, 이 앱은 그 출력을 읽어 표시만 한다.

## 설정

이 저장소에는 실제 경로·프로젝트 목록이 들어있지 않다. 처음 쓸 때:

```
cp config.example.js config.local.js
```

`config.local.js`를 열어 아래 두 값을 채운다(이 파일은 `.gitignore` 대상이라 커밋되지 않는다).

- `STATUS_SCRIPT`: 호출할 상태 스크립트의 절대경로. `-Json` 플래그를 받아서, 프로젝트별 상태 객체의 JSON 배열을 stdout에 찍어야 한다. 필요한 필드와 의미는 `config.example.js` 주석에 적어 뒀다. 저장소에 들어있는 `server-status.ps1`이 실제로 쓰는 예시 구현이다(포트·브랜치·미커밋·헬스를 그 순간 OS에서 직접 관찰, 등록부 파일 없음) — `java.exe` 커맨드라인에서 `<접두사><프로젝트명>`을 찾는 식이다. 네이밍 컨벤션이 완전히 다르면(접두사가 아니거나 `java.exe`가 아닌 런타임이면) 그 부분은 직접 고쳐 써야 한다. 모니터링할 프로젝트 목록·포트·접두사는 같은 폴더의 `servers.local.json`(없으면 `servers.example.json`)에서 읽는다 — 형식은 `{ "prefix": "...", "servers": [{ "name": "...", "port": 0 }, ...] }`. 급하게 한 번만 다른 접두사로 보고 싶으면 `-Prefix` 커맨드라인 파라미터가 그 파일의 `prefix` 값보다 우선한다.
- `PROJECT_ORDER`: 화면에 보여줄 프로젝트 이름(= 스크립트가 내는 `Project` 필드 값)과 그 표시 순서.
- `SHOW_BRANCH_INFO`: 기본값 `false`(숨김). `true`로 두면 2번째 칸(`[B]브랜치명 M<건수>`)과 범례의 해당 문구를 보여준다.
- `THEME`: 테두리·제목 색 테마 이름(기본값 `'peacock'`). 아래 "테마" 절 참고.

## 실행

```
npm install
npm start
```

`npm start`는 `node --watch index.js`라 소스를 고치면 자동으로 재시작된다(Node 18.11+ 내장 기능). 핫리로드가 아니라 "파일이 바뀌면 프로세스를 통째로 다시 띄우는" 방식이라 매번 수동으로 Ctrl+C → 재실행하던 걸 대신해 준다. 그냥 `node index.js`로 직접 띄워도 똑같이 동작하고 재시작만 안 될 뿐이다.

종료는 Ctrl+C. `digital-clock-board`처럼 터미널을 분할해서 한쪽에 띄워 두고 쓴다.

## 화면 구성

```
╭─────────────────────────────────────────╮
│ 서버 상태  (14:32:07 갱신)                │
│                                           │
│ service-a   8080        [B]main          │
│ service-b   18090       [B]feature/x...  │
│ service-c   -           -                │
│                                           │
│ [B] = 브랜치명, * = 포트가 기대값과 다름  │
╰─────────────────────────────────────────╯
```

- 1번째 칸: 포트. 비정상이면 포트 대신 헬스 상태(`응답없음`, `HTTP 5xx` 등)를 빨간색으로, 포트가 기대값과 다르면(`PortWarning` 필드가 비어있지 않으면) `*`를 붙여 노란색으로 표시한다. 중지된 프로젝트(`Location`이 `중지됨`)는 `-`.
- 2번째 칸: `[B]브랜치명`. 미커밋 변경(`Uncommitted` 필드)이 있으면 뒤에 `M<건수>`가 붙는다(`[B]feature/x M3`).
- 브랜치명이 터미널 폭보다 길면 줄바꿈된다. 한 줄로 자르던 버전도 있었지만(갱신마다 줄 수가 들쭉날쭉해 화면이 스크롤되는 것처럼 보이는 문제의 임시 대응이었다) 사용자 선호로 되돌렸다. 터미널 글자 크기를 줄여 쓰는 쪽으로 그 문제를 우회하는 중이다.
- 갱신에 실패하면(예: 상태 스크립트 호출 실패) 직전 값을 그대로 둔 채 제목에 `(HH:MM:SS 갱신 실패, 직전값 표시)`만 빨간색으로 띄운다. 죽지 않는다.

## 높이 — claude-agents-board와 같은 패턴

테두리는 내용 길이와 무관하게 처음부터 그 패널의 실제 행 수(`process.stdout.rows`)만큼 고정 높이로 뜬다 — 프로젝트 수가 적어서 내용이 짧아도 좌우 테두리가 패널 바닥까지 늘어난다(남는 자리는 빈 칸). 제목+프로젝트 줄 블록과 범례(`* = 포트가...` 줄)를 각각 하나의 자식으로 묶어, 바깥 Box에 `justifyContent: 'space-between'`을 줘서 둘을 양 끝에 고정했다 — 그래서 범례는 내용이 얼마나 짧든 항상 하단 테두리 바로 위 줄에 온다(남는 빈 줄은 둘 사이로 몰린다).

터미널이 내용보다도 더 작으면(실측: 8행짜리 터미널에 프로젝트 7개를 다 못 넣는 경우) Ink가 넘치는 줄을 그냥 잘라낸다 — 테두리 자체는 안 깨지지만 일부 프로젝트 줄이 안 보일 수 있다. `claude-agents-board`처럼 `n`키 페이지네이션은 아직 없다(요청받으면 그때 추가).

## 테마

테두리·제목 색은 `theme.js`의 `THEMES`에 이름별로 정의돼 있고(`cherry`, `ocean`, `peacock` 등 28개), `config.local.js`의 `THEME` 값으로 그중 하나를 고른다(모르는 이름이면 기본값 `peacock`으로 되돌아간다). 포트 상태색(정상/경고/에러/중지)과 기본 글자색은 테마와 무관하게 의미가 고정된 색이라 테마 객체 밖의 `STATUS_COLORS`에 따로 둔다 — 테마를 바꿔도 이 색들은 안 바뀐다.

named color(`'red'`/`'blue'`/`'magenta'` 같은 이름)는 터미널이 커스텀 색상표를 쓰면 재정의될 수 있다(실측: Tabby 커스텀 테마에서 `'magenta'` 테두리가 주황색으로 보임). 그래서 `theme.js`의 모든 값은 hex(`'#RRGGBB'`)로 적는다 — hex는 터미널 테마 재정의를 안 탄다.

새 테마를 추가하려면 `theme.js`의 `THEMES`에 `{ border, title }` 키 하나만 추가하면 된다. `--watch`로 떠 있으면 `config.local.js`의 `THEME` 값을 바꾸는 즉시 재시작되면서 반영된다. 실제 터미널 색은 스크린샷 없이는 비교하기 어려워서, `theme-swatches.html`을 브라우저로 열면 `THEMES`에 정의된 테마를 전부 한 화면에서 나란히 비교할 수 있다(`theme.js`에서 자동 생성되는 건 아니라 테마 목록이 바뀌면 이 파일의 `themes` 배열도 같이 고쳐야 한다).

## 알아두면 좋은 점 (삽질 기록)

- Windows PowerShell 스크립트를 `-File`로 바로 실행하면, 리다이렉트된 stdout의 비ASCII 문자(한글 등)가 시스템 코드페이지(예: CP949)로 깨져 나온다. 그래서 `index.js`의 `fetchStatus`는 `-Command`로 `[Console]::OutputEncoding = [System.Text.Encoding]::UTF8`을 먼저 설정한 뒤 스크립트를 호출한다. PowerShell이 아닌 다른 언어로 상태 스크립트를 짠다면 이 부분은 필요 없다.

## digital-clock-board와 폭 맞추기

Ink는 루트 `Box`의 너비를 매 렌더마다 터미널 전체 너비로 강제한다(값을 안 주면 저절로 내용에 맞춰 줄지 않는다 — 실측 확인). 그래서 `index.js`는 `string-width`로 그 순간 표시되는 줄들(제목·각 행·범례) 중 가장 긴 줄의 실제 터미널 칸 수를 재서 `paddingX: 1`×2 + 테두리 2를 더한 값을 `Box`의 `width`로 직접 지정한다. `SHOW_BRANCH_INFO`가 `false`면 2번째 칸과 범례 문구가 짧아지므로 이 값도 따라서 좁아진다.

옆에 띄우는 `digital-clock-board`는 이제 자기가 떠 있는 터미널 패널 폭에 맞춰 스스로 꽉 채우는 쪽으로 바뀌었다(이 쪽처럼 내용 기준으로 좁히는 게 아니라, 거꾸로 패널 폭을 그대로 따라간다 — 그쪽 README 참고). 그래서 더 이상 이 쪽 폭에 맞춰 `BOARD_WIDTH`를 역산해 두지 않는다. 나란히 맞춰 쓰려면 두 보드가 떠 있는 터미널 패널 폭 자체를 사용자가 맞추면 된다.
